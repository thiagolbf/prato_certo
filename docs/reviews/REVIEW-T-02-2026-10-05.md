### 🟡 Importantes

#### R-01 — O `next dev` criou `web/AGENTS.md` e `web/CLAUDE.md`, e o histórico registra o contrário

- **Eixo:** 1. Aderência ao plano
- **Referência cruzada:** T-02 (Camadas/arquivos afetados); CLAUDE.md da raiz ("Como trabalhar neste projeto"); fluxo do `/leanwork-context`
- **Evidência:**
  - `web/AGENTS.md` e `web/CLAUDE.md` criados às 20:42:14, durante a conferência do rewrite com `npm run dev`. O `create-next-app` tinha sido chamado com `--no-agents-md`.
  - `web/node_modules/next/dist/server/lib/app-info-log.js:126-128`: o `next dev` grava os dois arquivos quando detecta um agente de código no ambiente. O comentário do próprio Next indica a desativação por `agentRules: false` no `next.config`.
  - Plano, seção 11, linha da T-02: "`create-next-app` com `--empty` e `--no-agents-md` (sem `AGENTS.md`/`CLAUDE.md` gerado)".
- **Descrição:** os dois arquivos não estão na lista de arquivos da tarefa. O `web/CLAUDE.md` é, na prática, um contexto de módulo para o agente: contém só `@AGENTS.md`, e o `AGENTS.md` orienta a ler a documentação do Next.js em `node_modules/next/dist/docs/`. No pipeline, `CLAUDE.md` de módulo é escolha do desenvolvedor (`/leanwork-context modulo`), não algo que uma ferramenta cria sozinha. Além disso, a observação no histórico ficou incorreta: quem ler o plano vai acreditar que o arquivo não existe.
- **Sugestão de correção:** decidir entre duas saídas e corrigir a linha do histórico de acordo:
  1. **Manter e commitar.** O conteúdo é útil: o Next 16 mudou APIs (por exemplo, `middleware` virou `proxy`, ver Notas ao processo), e o arquivo aponta para a documentação da versão instalada. O próprio Next avisa que apagar o bloco só faz ele voltar no próximo `next dev`.
  2. **Desligar e apagar.** Pôr `agentRules: false` no `web/next.config.ts` e remover os dois arquivos, deixando o contexto de agente da Web para o `/leanwork-context`.

#### R-02 — ESLint 9 já está fora de suporte

- **Eixo:** 5. Qualidade do código
- **Evidência:** a instalação avisou `npm warn deprecated eslint@9.39.5: This version is no longer supported`; a versão atual é a 10.12.0. O `eslint-config-next@16.3.8` declara `peerDependencies: { eslint: ">=9.0.0" }`.
- **Descrição:** o `create-next-app` fixou `"eslint": "^9"`. O peer do `eslint-config-next` aceita o 10, mas não verifiquei se os plugins que ele traz (react, react-hooks, import, jsx-a11y) já funcionam no ESLint 10.
- **Sugestão de correção:** testar `npm i -D eslint@10` seguido de `npm run lint`. Se passar, manter; se algum plugin quebrar, ficar no 9 e registrar o motivo. Não precisa ser nesta tarefa.

## Verificação da Decisão Arquitetural

### ADR-002 — Next.js como frontend, com o app autenticado renderizado no cliente

- **Decisão original:** Next.js com App Router; as telas do app autenticado são client components; o Next.js também é a borda que reescreve `/api/*`.
- **Implementação:** projeto App Router (`web/src/app/`). A raiz `web/src/app/page.tsx:4-6` é um server component que só chama `redirect("/registrar")`. Ela não renderiza tela, então não contraria a regra dos client components. As telas autenticadas começam na T-38.
- **Conformidade:** ✅

### ADR-006 — Sessão por cookie httpOnly, com a API servida same-origin

- **Decisão original:** o Next.js reescreve `/api/*` para o backend, e o navegador enxerga uma única origem.
- **Implementação:** `web/next.config.ts:13-17` reescreve `/api/:path*` para `${API_URL}/api/:path*`, mantendo o prefixo `/api`. A partir da T-11, as rotas do FastAPI ficam sob `/api` e o `/health` fica fora dele, como na tabela de contratos da seção 3 do plano. Conferido de ponta a ponta: `GET /api/rota-inexistente` pela Web devolve o 404 JSON do FastAPI. Teste: `web/next.config.test.ts:16-22`.
- **Conformidade:** ✅

### ADR-008 — Desenvolvimento local primeiro, código portável sempre

- **Decisão original:** toda configuração vem de variável de ambiente, incluindo a URL da API usada pelo rewrite; nenhum recurso proprietário da Vercel.
- **Implementação:** `web/next.config.ts:5-11` lê `API_URL` sem valor padrão e falha se ela faltar. Conferido: `next build` e `next dev` param com "Defina API_URL (veja web/.env.example)". Teste: `web/next.config.test.ts:24-28`. O `web/.env.example` documenta a variável, e o `web/.gitignore` passou a versioná-lo (`!.env.example`). Nenhuma dependência de recurso da Vercel. O Node 24 fixado em `engines` deixa a versão local igual à que a Vercel vai usar na T-61.
- **Conformidade:** ✅

## Notas ao processo (não-findings)

- **Plano precisa de atualização (T-37):** a T-37 lista `web/src/middleware.ts`, mas no Next.js 16 o `middleware` foi renomeado para `proxy` (`proxy.ts`), que só roda no runtime Node.js. Vale ajustar o nome do arquivo na T-37 antes de executá-la e conferir se o limite de ritmo em memória continua valendo nesse runtime.
- **Escopo expandido, com justificativa:** além da lista da tarefa, entraram `web/next.config.test.ts` e `web/src/app/page.test.tsx` (testes dos critérios de aceite), `web/.nvmrc` e `engines` (versão do Node), `web/README.md` (troca o texto de exemplo, como a descrição pede), o título em `layout.tsx`, `!.env.example` no `.gitignore` e `vitest.config.mts` no lugar de `.ts` (o Vite 8 pede ESM). Tudo está justificado no histórico, e nada disso antecipa trabalho de outra tarefa. O `lang="pt-BR"` ficou para a T-35, como planejado.
- **Troca de Node:** a T-02 exigiu Node 24, porque o Vitest 5 e o jsdom 30 não rodam no Node 20, que está fora de suporte desde abril de 2026. O ambiente local agora usa nvm-windows com Node 24.21.0.
- **Ordem teste → código:** o teste do redirecionamento falhou antes da mudança no `page.tsx`. O do rewrite foi escrito depois do `next.config.ts` e não chegou a ser visto falhando. O executor declarou isso.
- **`npm audit`:** aponta 5 vulnerabilidades altas em `braces` (GHSA-vfj7-8cjw-p6xm), só na cadeia `eslint-config-next → @next/eslint-plugin-next → fast-glob → micromatch`, que é ferramenta de desenvolvimento e não vai para o bundle. O aviso marca todas as versões como afetadas, e o `--force` rebaixaria para o Next 14. Não aplicar; acompanhar.
- **Script de instalação bloqueado:** o npm 11 não executou o `postinstall` do `unrs-resolver`. O script (`napi-postinstall`) é um plano B caso falte o binário nativo opcional. O binário veio, e o `npm run lint` passa. Nenhuma ação necessária.
- **Contexto do agente:** com `web/` criado, o `/leanwork-context raiz` já consegue preencher Comandos e Testes no `CLAUDE.md`, como a própria T-02 prevê.
