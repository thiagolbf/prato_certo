### 🟢 Sugestões

#### R-01 — `/health` pode ficar pendurado até 60 s quando o banco não responde

- **Eixo:** 5. Qualidade do código
- **Referência cruzada:** ADR-008 (rota `/health` usada pelo ping e pelo health check da publicação)
- **Evidência:** `api/app/core/db.py:14-15`, `api/app/main.py:29-36`
- **Descrição:** o engine é criado sem `connect_args` de timeout, e o `asyncpg.connect` tem timeout padrão de **60 segundos**. Quando o banco recusa a conexão, como no teste, o 503 é imediato. Mas quando o host não responde (rede, pausa do Supabase, região), cada `GET /health` espera até 60 s antes de devolver 503. O teste `test_health_responde_503_sem_banco` não pega esse caso, porque usa um banco inexistente num servidor que responde.
- **Por que é Sugestão:** no ambiente local o efeito é invisível, e na T-01 nada consome o `/health` além do desenvolvedor. Passa a importar na Fase 8, quando o health check do Render (T-60) e o ping agendado (T-62) dependem dele.
- **Sugestão de correção:** passar `connect_args={"timeout": ...}` ao `create_async_engine` (poucos segundos) e envolver a consulta do `/health` num `asyncio.wait_for`, com teste que simule o banco lento. Pode entrar agora ou até a T-58, que prepara a API para produção.

#### R-02 — Testes importam utilitários de dentro do `conftest.py`

- **Eixo:** 5. Qualidade do código
- **Referência cruzada:** —
- **Evidência:** `api/tests/core/test_health.py:4`
- **Descrição:** `from tests.conftest import ConfiguracaoTeste, configuracao_para`. Hoje funciona porque `tests/` é pacote, mas importar o `conftest` como módulo comum é frágil: o pytest carrega o `conftest` por conta própria, e uma mudança de `rootdir` ou de modo de importação faz o mesmo arquivo ser carregado duas vezes, com duas cópias das classes.
- **Por que é Sugestão:** não quebra nada hoje; é prevenção, e o padrão vai se repetir em todos os testes que precisarem de um app com configuração própria.
- **Sugestão de correção:** mover `ConfiguracaoTeste` e `configuracao_para` para um módulo de apoio (por exemplo `tests/apoio.py`), importado pelo `conftest` e pelos testes; ou expor uma fixture-fábrica (`criar_app_com_banco(url)`) no `conftest`.

#### R-03 — Imagem base do `Dockerfile` sem versão fixa

- **Eixo:** 5. Qualidade do código
- **Referência cruzada:** ADR-008 (o mesmo `Dockerfile` roda local e no Render)
- **Evidência:** `api/Dockerfile:2`
- **Descrição:** `FROM python:3.12-slim` acompanha o patch mais recente do Python e a atualização do Debian. O `uv` está fixado em `0.9.9` e as dependências em `uv.lock`, mas o sistema base não: dois builds em dias diferentes podem gerar imagens diferentes, e a validação local (T-57) pode não reproduzir exatamente o que vai para o Render.
- **Por que é Sugestão:** risco baixo, e acompanhar os patches de segurança da imagem também tem valor.
- **Sugestão de correção:** fixar ao menos o patch e a distribuição (`python:3.12.x-slim-bookworm`) e atualizar de forma deliberada; ou registrar no README que a imagem flutua de propósito.

## Verificação da Decisão Arquitetural

### ADR-001 — Monolito modular em FastAPI, com deploy único

- **Decisão original:** um processo FastAPI, módulos por capacidade em pacotes próprios (*package by feature*), `core` transversal que não conhece nenhum módulo.
- **Implementação:** `api/app/{identidade,catalogo,vendas,relatorios}/__init__.py` criados vazios, com a responsabilidade de cada um; `api/app/core/` só importa bibliotecas externas; nenhuma pasta global por camada.
- **Conformidade:** ✅

### ADR-008 — Hospedagem em Vercel, Render e Supabase — desenvolvimento local primeiro, código portável sempre

- **Decisão original:** configuração por ambiente; API em `$PORT`; `/health` tocando o banco; nada em disco; PostgreSQL local na versão principal do Supabase; mesmo `Dockerfile` local e no Render.
- **Implementação:** `Configuracao` lê só do ambiente; `CMD` do `Dockerfile` usa `$PORT` (verificado pelo reviewer com `PORT=9123`); `/health` executa `SELECT 1` (`main.py:29-36`); nenhum código grava arquivo, e `PYTHONDONTWRITEBYTECODE=1` no container; `postgres:17`, conferido contra o changelog do Supabase; o Compose constrói a API pelo mesmo `api/Dockerfile`.
- **Conformidade:** ✅ — com a ressalva de robustez do R-01 para a fase de publicação.

### ADR-009 — Orientação a objetos seletiva

- **Decisão original (parte aplicável a esta tarefa):** injeção de dependência pelo `Depends`, sem container; nos testes, troca por `app.dependency_overrides`.
- **Implementação:** `obter_sessao` é função de dependência (`db.py:21-25`); o `conftest` troca a sessão por `app.dependency_overrides[obter_sessao]` (`conftest.py`, fixture `app`).
- **Conformidade:** ✅
