### 🟢 Sugestões

#### R-01 — Estados `herdado`, `futuroSemCardapio`, `sucesso` e `salvando` sem teste próprio

- **Eixo:** 4. Cobertura de teste
- **Descrição:** os quatro estados estão no código e foram exercitados manualmente pela leitura, mas não têm teste. O toast de sucesso aparece depois do `POST`.
- **Sugestão de correção:** acrescentar testes para "Confirmar este cardápio" (grava o herdado como próprio), para o vazio futuro e para o toast.

#### R-02 — Mensagens de erro por status

- **Eixo:** 5. Qualidade
- **Descrição:** o salvamento só mostra a mensagem da API para erros 4xx; os demais recebem texto neutro (RN-48). As outras telas do catálogo usam a mensagem da API em qualquer status. Como o tratamento de erro interno devolve texto genérico, o risco é baixo, mas a regra deveria ser a mesma em todas as telas.
- **Sugestão de correção:** centralizar em `lib/api.ts` a escolha entre mensagem de negócio (4xx) e texto neutro.
