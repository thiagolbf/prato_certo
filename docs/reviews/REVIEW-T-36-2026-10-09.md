A T-36 acrescenta `headers()` ao `web/next.config.ts`, com HSTS, `X-Content-Type-Options: nosniff`, `X-Frame-Options: DENY` e uma CSP com `default-src 'self'`, `frame-ancestors 'none'` e sem domínio externo. `unsafe-eval` só entra em desenvolvimento. ### 🟡 Importantes

#### R-01 — O critério "sem erro de CSP no console" não foi verificado

- **Eixo:** 1. Aderência ao plano
- **Referência cruzada:** plano, T-36, critério 2; CA-41 (lado Web)
- **Evidência:** a verificação desta tarefa rodou `npm run build`, `npm start` com `curl` e os testes. Não houve abertura da página num navegador, e o console não foi lido.
- **Descrição:** a CSP foi escrita com `script-src 'self' 'unsafe-inline'`. O Next pode gerar scripts inline que a CSP bloqueie, o que apareceria só no console do navegador. O cabeçalho chega ao cliente, mas não se sabe se o app roda sem violação.
- **Por quê é Importante:** o plano coloca essa checagem como critério. Sem ela, a tarefa não pode ser dada como concluída.
- **Sugestão de correção:** abrir `http://localhost:3000/` com `npm run build && npm start` e a API no ar (ou sem ela, só a página estática) no Chrome, com o console aberto, e registrar se aparece `Refused to ... because it violates the following Content Security Policy directive`. Se aparecer, ajustar a CSP e repetir. Ao concluir, marcar o critério e voltar a tarefa para `Concluído`.

### 🟢 Sugestões

#### R-02 — `script-src` usa `'unsafe-inline'` também em produção

- **Eixo:** 3. Aderência ao spec
- **Referência cruzada:** plano, T-36, "Ajustar o necessário para os scripts do Next.js funcionarem sem abrir `unsafe-eval` em produção"
- **Evidência:** `web/next.config.ts`, função `cabecalhosDeSeguranca`: `script-src 'self' 'unsafe-inline'` em produção.
- **Descrição:** o plano só proíbe `unsafe-eval`, e `unsafe-inline` é a forma mais simples de deixar os scripts inline do Next funcionarem. Uma CSP com nonce seria mais restritiva, mas exige middleware e mudança na renderização. Como as telas do app são client components (ADR-002), o ganho tende a ser pequeno.
- **Sugestão de correção:** registrar a decisão como risco aceito na seção de riscos da arquitetura, ou abrir tarefa própria para CSP com nonce se o app crescer em superfície.
