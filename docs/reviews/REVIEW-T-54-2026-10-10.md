### 🟢 Sugestões

#### R-01 — "Senha atual incorreta" e "conta bloqueada" usam a mesma mensagem da API

- **Eixo:** 3. Aderência ao spec
- **Evidência:** `web/src/app/(app)/conta/senha/page.tsx` mostra a mensagem que a API devolve no 422, que cobre senha atual errada e conta bloqueada.
- **Descrição:** é o comportamento pedido pela RN-37 (a conta bloqueada não se distingue da senha errada). Registrado para conferência.
- **Sugestão de correção:** nenhuma.

#### R-02 — Senha curta é checada no cliente com a mesma regra da API

- **Eixo:** 5. Qualidade
- **Evidência:** a checagem de tamanho mínimo está em `validar()` com a constante `MINIMO = 8`.
- **Descrição:** a regra vem da RN-60 e está duplicada no cliente. A API também valida (`SenhaNova`). Aceitável como atalho de interface; o limite de 72 bytes ainda não é checado no cliente.
- **Sugestão de correção:** checar também o limite de 72 bytes UTF-8 quando a tela for revisada no celular.

## Cobertura por RN

- **RN-53:** a troca usa a rota de conta própria do ADMIN, com a senha atual exigida. Coberto.
- **RN-60:** mínimo de 8 caracteres checado no cliente; o máximo de 72 bytes fica na API (R-02).
