### 🟢 Sugestões

#### R-01 — Estados `validacao`, `enviando`, `sessaoExpirada` e `erro` sem teste próprio

- **Eixo:** 4. Cobertura de teste
- **Evidência:** `web/src/app/login/login.test.tsx` cobre 401, 429, `saiu` e sucesso. Os outros quatro estados estão no código de `FormularioEntrar.tsx`, mas sem teste.
- **Descrição:** o critério "os oito estados renderizam como na SPEC-UI" é verificado por leitura, não por teste.
- **Sugestão de correção:** acrescentar testes de campo vazio, de envio em andamento e de `motivo=sessao-expirada` quando a tela for revisada no celular (T-45).

#### R-02 — Duas instâncias do cliente HTTP

- **Eixo:** 5. Qualidade do código
- **Evidência:** `FormularioEntrar.tsx` cria `apiLogin = criarClienteApi(() => undefined)`, separado do `api` padrão.
- **Descrição:** é deliberado, para que um 401 de login não vire redirecionamento de sessão expirada. Está comentado no arquivo. O custo é pequeno, mas é uma segunda forma de chamar a API a manter.
- **Sugestão de correção:** nenhuma agora; reavaliar se surgir outra chamada sem sessão.
